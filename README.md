# Приватка — бот

## Запуск
```
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_IDS
python bot.py
```

## Фото для /start
По умолчанию бот использует два `file_id`, зашитых в `config.py`
(`DEFAULT_OPEN_PHOTO_ID` / `DEFAULT_CLOSED_PHOTO_ID`). Важно: `file_id`
привязан к конкретному боту — картинка, загруженная в другого бота
(например, при пересылке скрина), в твоём боте может не открыться. Если при
первом же `/start` увидишь ошибку `wrong file identifier` — просто пришли
нужные фото своему боту реплаем на команды `/set_open_photo` /
`/set_closed_photo`, он сам возьмёт актуальный `file_id`.
- `/start` показывает фото + меню. Если набор открыт — есть кнопка
  «войти в приватку», иначе её нет и показывается другое фото/текст.
- Кнопки «что внутри?», «отзывы», «задать вопрос» — обычные URL-кнопки на
  telegra.ph и t.me, менять их не нужно (заданы в `config.py`).
- `/admin` (только для ID из `ADMIN_IDS`) — кнопка «Открыть набор» /
  «Закрыть набор», переключает состояние в БД.
- `/set_open_photo` и `/set_closed_photo` — отправь админом реплаем на фото,
  чтобы задать картинки для открытого/закрытого набора.

## Способы оплаты
После «войти в приватку» бот показывает выбор: **картой** (ЮKassa,
редирект-страница), **СБП** (тоже через ЮKassa, но напрямую — бот сам рисует
QR и присылает картинкой, без промежуточной страницы), **CryptoBot** и
**xRocket** (оплата криптой, оба через официальные Pay API этих сервисов).
Каждый способ независим — если не подключишь какой-то из провайдеров,
остальные продолжат работать, а при нажатии на неподключённый бот просто
объяснит, что ещё не готово.

- **ЮKassa (карта + СБП)** — см. раздел выше, там же берутся оба ключа.
- **CryptoBot** — токен из @CryptoBot: `/pay` → Create App → API Token →
  `CRYPTOBOT_API_TOKEN` в `.env`. Список принимаемых крипто-активов —
  `CRYPTOBOT_ACCEPTED_ASSETS` (по умолчанию USDT, TON, BTC), сама сумма
  инвойса выставляется в рублях и конвертируется по курсу CryptoBot.
- **xRocket** — токен из @xRocket: Pay API → Create an app → Settings →
  API Token → `XROCKET_API_TOKEN` в `.env`. Важно: в настройках приложения
  должно быть выбрано **API Version: Current** (новый Pay API), а не Legacy —
  форматы запросов у них разные. Валюта инвойса — `XROCKET_ASSET` (по
  умолчанию USDT).
  ⚠️ Пометка на будущее: реализация xRocket написана по самой свежей
  публичной документации на момент кода, но это совсем новая версия их API
  (Legacy → Pay API) — после того как получишь токен, стоит один раз
  прогнать `/check_payment` на тестовом платеже и свериться со Swagger
  приложения (`https://pay.api.xrocket.exchange/api/docs/`), что поля запроса
  и ответа (`xrocket_payments.py`) совпадают. Если что-то разойдётся —
  пришли ответ API, поправлю за минуту.

Логика диспетчеризации по провайдерам (какой статус значит «оплачено», какой
проверять) вынесена в `payment_dispatch.py`, чтобы не дублировать между
`/check_payment` и автопроверкой.

## Выдача доступа в приватку (одноразовая ссылка)
1. Добавь бота в приватный канал/группу админом с правом
   **«Приглашать пользователей по ссылке»** — без этого он не сможет ни
   создавать инвайты, ни одобрять заявки.
2. Узнай ID канала (можно переслать любое сообщение из него боту
   [@userinfobot](https://t.me/userinfobot) или через `getChat`) и впиши в
   `.env` как `PRIVATE_CHANNEL_ID` (вид `-100xxxxxxxxxx`).
3. Как только оплата подтверждена (см. ниже), бот сам:
   - создаёт инвайт-ссылку с `creates_join_request=True` — по ней нельзя
     войти сразу, только отправить заявку;
   - присылает её оплатившему;
   - когда тот жмёт и подаёт заявку, бот получает апдейт, сверяет, что
     заявка от того же user_id и по той же ссылке, одобряет её;
   - сразу отзывает (`revoke`) ссылку — второй раз ей уже не воспользоваться,
     и чужая заявка по этой же ссылке будет отклонена.
   Логика — в `access.py` и `handlers/join_request.py`.

## Подключение ЮKassa (когда пройдёте проверку)
1. Впишите `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в `.env` — ничего в
   коде менять не нужно, `payments.py` подхватит их сам.
2. После нажатия «войти в приватку» бот создаёт платёж, присылает ссылку на
   оплату и сам начинает поллить статус (`_poll_payment_and_grant`, раз в
   15 сек, до 15 минут) — как только видит `succeeded`, сразу выдаёт
   инвайт-ссылку, без участия админа. Плюс на всякий случай остаётся ручная
   проверка: `/check_payment <id>`.
3. Поллинг — временное решение, пока нет вебхука. Для мгновенной и более
   надёжной выдачи (и чтобы не зависеть от того, жив ли процесс, пока юзер
   ждёт) лучше принимать вебхуки от ЮKassa (`payment.succeeded`) — нужен
   внешний HTTPS-домен. `payments.parse_webhook_event()` для этого уже готов,
   останется поднять aiohttp-обработчик, если решишь перейти на webhook-режим
   на BotHost (у тебя это уже было в `shop_bot`, домен вида `*.bothost.tech`).

## Деплой на BotHost
Дефолтный режим — polling (`bot.py` просто запускается процессом, как в
`shop_bot`/`test7shop`), отдельный домен не нужен. Не забудь в панели
BotHost задать переменные окружения из `.env` (или сам `.env`-файл, смотря
как у тебя настроен запуск), и что процесс должен быть persistent
(polling — это бесконечный цикл, а не одноразовый скрипт).

## Структура
```
bot.py                     — точка входа, polling
config.py                  — все настройки и ссылки
database.py                — aiosqlite: набор, фото, платежи, инвайты
payments.py                — ЮKassa: карта + СБП
cryptobot_payments.py      — CryptoBot (Crypto Pay API)
xrocket_payments.py        — xRocket (Pay API)
payment_dispatch.py        — общая диспетчеризация статусов по провайдерам
access.py                  — выдача одноразовой инвайт-ссылки
keyboards.py                — инлайн-клавиатуры
handlers/user.py           — /start, выбор способа оплаты, поллинг статуса
handlers/admin.py          — /admin, переключение набора, фото, /check_payment
handlers/join_request.py   — приём и одобрение заявок на вступление в приватку
```
